# Contributing

## Development Workflow
1. Make a focused change.
2. Run the relevant module or test.
3. Run the full test suite before final sign-off.
4. Review generated files and `git status`.
5. Commit only intentional source and deliverable changes.

## Code Quality
- Keep calculations reproducible.
- Prefer explicit column names and documented assumptions.
- Preserve project paths and output conventions.
- Do not silently replace anomalous source data with invented values.

## Pull Requests
Describe the change, validation performed, affected outputs and known data-quality limitations.
